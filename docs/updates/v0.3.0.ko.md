# Jev Skill Router 0.3.0

[English](v0.3.0.md) | [한국어](v0.3.0.ko.md)

**API 호출 전 제한을 확인하고, 긴 파일을 같은 버전으로 이어 읽으며, 잘못된 MCP 입력 뒤에도 서버가 계속 응답하도록 개선했습니다.** 로컬 동작의 안정성과 진단을 보완한 업데이트이며, 실제 Jev 판단 정확도나 비용 개선을 입증한 버전은 아닙니다.

## 주요 변경

| 항목 | 이전 동작 | 0.3.0 |
| --- | --- | --- |
| 요청 사전 점검 | 실제 라우팅 내부에서만 한도 확인 | `jev-skills plan`으로 키 조회·API 호출 없이 같은 한도 확인 |
| 긴 파일 이어 읽기 | 중간에 파일을 수정하면 서로 다른 버전이 섞일 수 있음 | 각 페이지의 파일 버전을 확인한 뒤 이어 읽기 |
| 안내용 스킬 | 라우터가 자기 안내용 스킬을 후보로 선택할 수 있음 | 예약 이름 `jev-skill-router`를 후보에서 제외 |
| 스킬 탐색 | 경로 표기에 따라 중복 등록되거나 읽지 못한 하위 폴더가 조용히 누락될 수 있음 | 경로 안전성 확인 후 중복 통합, 읽기 실패 경고 표시 |
| 오류 안내 | 메타데이터 오류가 예외 종류로만 표시되는 경우 있음 | 잘못된 YAML 내용을 노출하지 않고 수정할 원인 안내 |
| MCP 연결 | 깊은 JSON·잘못된 유니코드 입력으로 서버가 종료될 수 있음 | 오류 응답 후 다음 요청 처리 |
| 설치 제한 | 설정된 값 대신 기본 스킬 수 제한 사용 | `max_catalog_skills` 설정값 적용 |

## 기존 사용자 업데이트

[현재 소스 ZIP](https://github.com/himomohi/jev-skill-router/archive/refs/heads/main.zip)을 내려받아 압축을 풀거나, 로컬 수정이 없는 Git 체크아웃에서 `git pull --ff-only`를 실행하세요. 아래 명령은 저장소 최상위 폴더에서 **기존 MCP 서버에 등록된 Python 환경**을 대상으로 실행합니다.

안내형 설치 프로그램으로 설치한 macOS/Linux 환경:

```bash
"${JEV_SKILLS_HOME:-$HOME/.jev-skill-router}/runtime/bin/python" -m pip install --upgrade '.[secure]'
"${JEV_SKILLS_HOME:-$HOME/.jev-skill-router}/runtime/bin/python" -c "from jev_skill_router import __version__; print(__version__)"
```

안내형 설치 프로그램으로 설치한 Windows PowerShell 환경:

```powershell
$jevHome = if ($env:JEV_SKILLS_HOME) { $env:JEV_SKILLS_HOME } else { Join-Path $HOME '.jev-skill-router' }
& (Join-Path $jevHome 'runtime\Scripts\python.exe') -m pip install --upgrade '.[secure]'
& (Join-Path $jevHome 'runtime\Scripts\python.exe') -c "from jev_skill_router import __version__; print(__version__)"
```

직접 관리하는 가상환경은 기존 환경을 활성화한 뒤 `python -m pip install --upgrade '.[secure]'`를 실행하세요. 키체인 지원 없이 설치한 환경이라면 `'.[secure]'` 대신 `'.'`을 사용합니다. 의존성 설치에는 네트워크가 필요합니다. 이 명령은 패키지만 교체하므로 기존 루트·모드·클라이언트 등록을 변경하거나 스킬을 이동하지 않으며, API 키를 다시 입력받지 않습니다.

업데이트 후 MCP 서버 또는 연결한 앱을 재시작해 새 코드와 도구 스키마를 불러오세요. 기존 실행 경로나 동일한 Python의 `-m jev_skill_router`로 확인합니다.

```bash
jev-skills doctor
jev-skills plan "Python 오류와 실패한 테스트를 디버깅해줘"
```

두 명령은 Jev를 호출하지 않습니다. `doctor`는 스킬 목록의 경고도 보여주고, `plan`은 캐시를 사용하지 않는 새 요청의 보수적인 상한을 계산합니다. `ready: true`여도 인증 성공이나 충분한 처리 시간·재시도를 보장하지 않습니다. `doctor --live`와 평가 도구의 `--allow-live`는 실제 API 사용량을 발생시킵니다.

## 직접 연동한 클라이언트의 변경 사항

첫 페이지 읽기는 기존처럼 동작합니다. 결과의 `next_offset`이 null이 아니라면 같은 파일의 `content_digest`와 함께 다음 페이지를 요청하세요.

```python
next_page_arguments = {
    "action": "read",
    "skill_id": previous_page["skill_id"],
    "path": previous_page["path"],
    "offset": previous_page["next_offset"],
    "expected_digest": previous_page["content_digest"],
}
```

CLI에서는 `--offset OFFSET --expected-digest DIGEST`를 전달합니다. 0보다 큰 오프셋에서 digest가 없으면 거부합니다. 파일 버전이 달라졌다면 앞서 받은 페이지를 버리고 처음부터 읽으세요. `SKILL.md`가 바뀌었다면 다시 라우팅합니다. 참조 파일은 자체 digest를 사용합니다. Python `Catalog.read` 직접 호출 시에도 같은 검증을 원하면 `expected_digest`를 전달해야 합니다.

## 검증 결과와 범위

- Linux / Python 3.12 로컬 테스트 **199개 통과**, Windows 전용 **2개 제외**. 실제 Jev 응답 대신 통제된 테스트 응답을 사용했습니다.
- 평가 사전 점검 **24개 사례**: 영어 12개, 한국어 12개. **API 요청과 키 조회 모두 0회**입니다.
- 실제 별도 프로세스에서 잘못된 MCP 입력 뒤에도 한글·이모지 ID가 있는 ping에 응답하는 것을 확인했습니다. 파일 수정·축소, 중복 경로, 안내용 스킬 제외, 요청 계획도 회귀 검증했습니다.
- 게시된 커밋의 플랫폼별 CI 결과는 [GitHub Actions](https://github.com/himomohi/jev-skill-router/actions/workflows/test.yml), 검증한 정확한 리비전은 [검증 기록](../VALIDATION.md)에서 확인할 수 있습니다.
- 실제 Jev 판단 정확도·청구 비용, 데스크톱 앱 사용과 운영체제 키체인은 아직 검증하지 않았습니다. MCP 서버는 요청을 순서대로 처리하므로 호스트의 취소 알림으로 진행 중 라우팅을 즉시 중단하지는 못합니다. 내부 오류와 시간 제한에 따른 HTTP 요청 취소는 적용됩니다.

새 합성 비교에서 스킬 200개의 관련 데이터는 **58,088 → 4,845 UTF-8 바이트, 91.66% 감소**입니다. 0.2.1의 92.31%보다 감소율이 작아진 이유는 도구 스키마와 파일 버전 정보가 늘었기 때문입니다. 스킬이 5개면 오히려 24.88% 증가합니다. 실제 토큰·전체 대화 비용·작업 속도가 아닌 스킬 관련 바이트 비교입니다. [계산 방법](../BENCHMARKS.md).
