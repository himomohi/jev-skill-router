# Jev Skill Router 0.3.0

[English](v0.3.0.md) | [한국어](v0.3.0.ko.md)

**Check request limits before spending, keep file pages on the same revision, and recover from malformed MCP input.** This update improves local reliability and diagnostics. It does not claim improved live Jev selection accuracy or lower billed cost.

## What changed

| Area | Previous behavior | 0.3.0 |
| --- | --- | --- |
| Request planning | Limits were checked inside live routing | `jev-skills plan` exposes the same conservative bounds without keys or requests |
| Long-file reads | A file edit between pages could mix revisions | Every page carries a digest; continuation must match it |
| Router bridge | The installed bridge could become a selection candidate | The reserved `jev-skill-router` name is excluded |
| Catalog discovery | Alternate root spellings could duplicate a skill; unreadable subdirectories could disappear silently | Root aliases are deduplicated after safety checks; unreadable directories produce warnings |
| Diagnostics | Metadata warnings often showed only an exception class | Fixed, actionable error reasons are returned without quoting invalid YAML |
| MCP transport | Deep JSON or invalid Unicode could terminate a session | Bad frames receive an error and following requests can still be served |
| Setup limits | Setup used the default catalog limit | Setup honors the configured `max_catalog_skills` |

## Update an existing installation

Download/extract the [current source](https://github.com/himomohi/jev-skill-router/archive/refs/heads/main.zip), or update your clean Git checkout with `git pull --ff-only`. Run the relevant command from the repository root, using the same Python environment as your registered MCP server.

For the guided installer runtime on macOS/Linux:

```bash
"${JEV_SKILLS_HOME:-$HOME/.jev-skill-router}/runtime/bin/python" -m pip install --upgrade '.[secure]'
"${JEV_SKILLS_HOME:-$HOME/.jev-skill-router}/runtime/bin/python" -c "from jev_skill_router import __version__; print(__version__)"
```

For the guided installer runtime in Windows PowerShell:

```powershell
$jevHome = if ($env:JEV_SKILLS_HOME) { $env:JEV_SKILLS_HOME } else { Join-Path $HOME '.jev-skill-router' }
& (Join-Path $jevHome 'runtime\Scripts\python.exe') -m pip install --upgrade '.[secure]'
& (Join-Path $jevHome 'runtime\Scripts\python.exe') -c "from jev_skill_router import __version__; print(__version__)"
```

For a manually managed virtual environment, activate the existing environment and run `python -m pip install --upgrade '.[secure]'`. If your installation deliberately omits keychain support, use `'.'` instead of `'.[secure]'`. Dependency installation requires network access. The commands update the package in place; they do not run setup, change roots/mode, re-register clients, move parked skills or prompt for a key.

Restart the MCP server or its host after updating so the process loads the new package and tool schema. Then use the existing launcher (or the same Python with `-m jev_skill_router`):

```bash
jev-skills doctor
jev-skills plan "Debug Python tracebacks and failing tests"
```

Neither command calls Jev. `doctor` also reports catalog warnings; `plan` checks conservative fresh-route bounds. `ready: true` does not verify authentication or guarantee enough time/retries. `doctor --live` and the evaluator's `--allow-live` make real, potentially billable requests.

## Pagination change for custom clients

First-page reads still work. Each result now includes `content_digest`. When `next_offset` is not null, pass that value as `offset` and the digest for the same file as `expected_digest`:

```python
next_page_arguments = {
    "action": "read",
    "skill_id": previous_page["skill_id"],
    "path": previous_page["path"],
    "offset": previous_page["next_offset"],
    "expected_digest": previous_page["content_digest"],
}
```

CLI equivalents are `--offset OFFSET --expected-digest DIGEST`. An offset greater than zero without a digest is rejected. On a revision mismatch, discard accumulated pages and restart reading; reroute a changed `SKILL.md`. Reference files have separate digests. Python `Catalog.read` callers must explicitly pass `expected_digest` to enforce the same check.

## Verification and limits

- Local Linux / Python 3.12 suite: **199 passed**, **2 Windows-only tests skipped**. Tests use controlled provider fixtures, not live Jev answers.
- Evaluation preflight: **24 cases**, 12 English and 12 Korean; **zero API requests and credential reads**.
- Subprocess checks verify that invalid frames return errors and a subsequent Unicode-ID ping succeeds. Regression cases cover edited/truncated files, root aliases, bridge exclusion and request planning.
- [Cross-platform CI](https://github.com/himomohi/jev-skill-router/actions/runs/35737405992) passed on commit `f1e0607`: Ubuntu Python 3.11/3.13 and macOS Python 3.12 each passed 199 tests with 2 Windows-only skips; Windows Python 3.12 passed all 201. Package installation, context accounting and evaluator preflight also passed in all four environments. See the [validation record](../VALIDATION.md).
- Live Jev accuracy, billed cost, real desktop-client sessions and OS keychains remain unverified. The serial MCP server cannot interrupt a running route on a host cancellation notification; its own errors/deadline still cancel pending HTTP work.

The refreshed synthetic 200-skill comparison is **58,088 → 4,845 UTF-8 bytes (91.66%)**. The earlier 0.2.1 figure was 92.31%; the larger schema and revision metadata add overhead. Five skills produce 24.88% more modeled context. These are skill-related payload counts, not tokens, whole-conversation cost or end-to-end speed. [Method](../BENCHMARKS.md).
