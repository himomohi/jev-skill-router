# Jev Skill Router 0.4.0

[한국어 업데이트 안내](https://github.com/himomohi/jev-skill-router/blob/v0.4.0/docs/updates/v0.4.0.ko.md)

This update strengthens cancellation, large-catalog handling, upgrade safety and independently reproducible checks. It does not claim a measured live Jev accuracy, speed or billing improvement.

## Changes

- MCP cancellation interrupts active network/retry waits and removes queued work. The reader stays responsive to ping. One worker owns router state and closes its pool on shutdown; the accepted tool-call queue is bounded to 16. Cancelled requests emit no result. Already accepted provider work may still be billed, and local filesystem work remains cooperative at phase boundaries.
- Add explicit `candidate_strategy=indexed` and `candidate_limit` (production default 64). A cached metadata-only BM25 index narrows large catalogs before normal Jev ranking/verification. Results disclose the evaluated scope and cutoff ties. Default `all` retains full-catalog consideration; small catalogs stay complete even in indexed mode. No lexical overlap stops before credential lookup or API calls.
- Add `Install.py --upgrade` with config preservation and installed-version verification. Preserve roots, mode, credentials, registration and custom launchers. Fresh installation detects existing config and directs users to upgrade. Repeated identical host registration is idempotent; conflicting entries remain untouched. Codex registration explicitly forwards the environment key by name without storing its value.
- Repeated setup preserves the routing mode. Use `--live` or `--offline` to change it explicitly. Add `jev-skills --version`.
- Add 96 original English/Korean challenge cases, independent BM25 top-1 and threshold baselines, candidate-retention checks, shared-budget live strategy comparison and strict import of caller-scored paired host trials.
- Verify real stdio interoperability with official MCP Python SDK 1.30.0. Verify actual Codex CLI 0.155.1 and Claude Code 2.1.278 registration/connection in disposable profiles. These are not model-driven task success trials.
- Publish versioned wheel, sdist, source ZIP and SHA256SUMS from a successful main Tests SHA. The publisher checks version/changelog alignment, preserves existing tags/assets and resumes interrupted drafts by verifying bytes.

## Upgrade

From the new source checkout or extracted source ZIP:

```bash
python Install.py --upgrade --non-interactive
# Add --no-keychain if using core-only dependencies and environment credentials.
jev-skills --version
```

Use the same `JEV_SKILLS_HOME` as before, then restart your host session. A pip-managed installation can use `python -m pip install --upgrade '.[secure]'` in the existing environment. Existing configuration files use defaults for new fields. First-page and digest-bound continuation reads remain compatible with 0.3.0.

Try large-catalog narrowing without persisting a setting:

```bash
jev-skills plan "Inspect specialist operation" --candidate-strategy indexed --candidate-limit 64
```

`all` remains recommended when full-catalog semantic recall is required. The authored 16-skill challenge with limit 8 retained 83/92 required candidates; missing candidates cannot be recovered by later Jev verification. This is not Jev accuracy.

## Evidence and limits

- Synthetic 4,096-skill request planning: full catalog requires up to 58 base requests and is blocked by the default 32-attempt cap; indexed limit 64 requires up to 2 for this fixture. Neither result is measured API cost or latency.
- Current synthetic 200-skill context accounting: 58,088 → 4,940 UTF-8 bytes (91.50%). Five skills increase modeled context by 27.28%. These are not model tokens or total conversation savings.
- Isolated 0.3.0 → 0.4.0 guided upgrade passed: identical config bytes, offline mode and six skills preserved, launcher reports 0.4.0. No keychain or API use.
- Local comparison: BM25 top-1 exact-set matches 60/96; threshold baseline 53/96. Live Jev has no measured result. Cases are project-authored, not independent holdout evidence.
