# Technical documentation

Lead with the actual user outcome. Explain prerequisites and provide one tested installation path.
Separate runnable examples from illustrative snippets and label placeholders.
Explain authentication without putting secrets in source, URLs, logs, or screenshots.
Describe verified behavior, known limitations, and how a reader can reproduce verification.
Keep linked files relative within the repository. Use an English README by default and link to a Korean README when both are provided.
Avoid unsupported performance, compatibility, security, or production-readiness claims.
